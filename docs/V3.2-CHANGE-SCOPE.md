# V3.2.0 修改范围

本次采用第 4 包「产品体验与可玩性」；Tournament & Evaluation 顺延到 V3.3。
基线直接来自 V3.1.0 Delivery，附带 Validation 记录 215 项测试通过；开工不重复完整回归。

## A：房间资源治理

- `app/game.py`：兼容增加暂停时间与剩余倒计时字段。
- `app/rules.py`：增加暂停/继续 hook，不改旧角色胜负规则。
- `app/rooms.py`：重连宽限、主动退出、任务取消、闲置卸载。
- `app/persistence.py`：暂停 TTL 与彻底删除，复用 JSON 快照，兼容旧库。
- `app/main.py`：增加继续与删除 endpoint，接入 WebSocket 离线通知。
- `tests/test_v32_rooms.py`：验证取消请求、冻结/恢复、卸载和隐私清理。

不涉及 Provider 接口、BYOK 凭据格式、Arena Runner、Docker。

## B：声音、发言节奏与模型偏好

- `app/static/js/audio.js`、独立本地音频素材：分轨混音、BGM、主持语音、解锁反馈。
- 独立 `pacing.js` 和必要的 `game.js` / `events.js` hook：纯展示缓冲，不延长服务端请求。
- `app/ai.py`、`app/game.py`、`app/llm.py`：发言建议长度、合理输出上限、首 token/真实生成统计。
- 模型中心/座位选择 UI、偏好 API 和小型增量表：身份关联收藏、最近调用状态、阵容预设。

不涉及模型战略代决策、凭据明文回显、比赛逻辑。

## C：App Shell 与玩法

- 现有 HTML/CSS 与独立 `shell.js`：五项导航、首页/战绩/我的，游戏沉浸态。
- `app/roles.py`、新 `app/boards.py`：固定板、标签约束随机、自定义池、四个完整角色。
- 现有 `game.py` / `rules.py` / `scope.py` 的直接技能调度 hook：身份与实际随机板保密。
- API、AI 动作 schema、前端角色说明：只补直接依赖，不重写引擎。

不涉及联赛/评分/Judge/并发 Runner、外部 SDK、部署架构或依赖升级。

## 验证与交付

开发中只做受影响模块的定向测试；功能集成后一次完整回归、静态检查、浏览器验收。
完成后对照原始 Delivery 检查改动文件；无关问题记入 FOLLOW-UP。
更新版本、API 与验收说明，生成源码与验证包，明确 Mock / 真实 Provider 证据边界。
