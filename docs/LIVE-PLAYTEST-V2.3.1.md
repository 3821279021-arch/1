## 发现并修复

1. **中文 Token 的冷启动预估过高。**旧经验估算在前 3 次代表性请求上高估 65.47%–83.26%，之后才按 Usage 校准；DashScope 预算还计入了实际没有发送的原生 schema。现在随包提供 Qwen 公开词表，用本地 ByteLevel BPE 计数，区分消息封装开销，移除多算的 schema，保留默认 15% 安全余量。词表的来源、许可证与 SHA-256 见 `app/tokenizers/README.md`。
2. **复杂摘要能穿透 Prompt 上限。**旧裁剪只缩短几类列表和最近事件；六人反复改变身份、报告多目标查验时，默认 5,400 Token 的上下文目标仍会得到 5,644 Token 的 Qwen 文本。现在继续裁剪低优先级摘要和重复策略字段，在 6,000/3,000/1,800 的配置下保留自身已确认查验并满足对应上下文预算。只裁剪本次请求，存储记忆保持原样。
3. **否定和转述误归因。**“我查验了2号，他不是狼”被记成未公布结果；别人转述查验又可能成为当前发言人的查验声称。现在识别否定的好人结果，保留未确认标记，并避免把转述或追问当成说话人自己的报告。新增测试同时保护正常连续报告和立场矛盾检测。
4. **预言家报错自己的结果。**基线中实际查到狼人，却公开说“他不是狼”。现在真实预言家的已确认查验由服务器生成准确前缀；模型接续观点，涉及新增或改写查验的接续句被过滤。其他玩家的声称不能进入这一前缀。专项测试模拟跨 SSE 碎片的错误改写，真实 Qwen 测试也验证了正确报告。
5. **公开表达编造沉默、泄露技能措辞。**旧完整私人上下文使 AI 在首位发言时质疑尚未发言的人，或公开使用“我未刀人”等措辞。现在表达模型只接收公开投影和计划，去掉狼聊、队友和隐藏概率；完整句子在入公共记录前检查。最终补跑拦截 1 句，其余发言正常送出，未触发整段安全替换。
6. **分词和裁剪拖慢事件循环。**引入真实分词后，旧同步上下文计算会拖慢极短回合压力测试。上下文构造移到后台线程，预算计算缓存重复文本；原完整 Mock 对局和慢计算时钟回归重新通过。

同时修复旧真实实测脚本与新的 SQLite 保存签名不兼容，以及后备测试 HTTP Client 未关闭的问题。脚本现在记录版本、房间/天数、成本分组和发言保护计数。

## 真实 Usage 与浏览器专项

用第 1/5/15/30 天和复杂 30 天的**合成历史**调用真实接口；这些不是完整 30 天付费对局。最终三个模型 15 个动作样本的预估误差中位数为 **15.01%**，最大约 **15.02%**，满足 <20% 验收；误差包含主动预留的 15% 安全余量。未加余量的原始输入计数在本批样本中与实际 Usage 一致。另有 3 次真实预言家流式输出，全部正确保留已确认查验。

手机尺寸 Chromium（390×844）通过 UI 将搭档设为 Qwen，真实私聊 2 次。真实接口、WebSocket、持久化成本报告均正常，JavaScript 无错误，Key 不在 DOM/localStorage/客户端快照中。截图：`previews/v231-live-mobile-pet.png`；报告：`playtests/v231-live-browser.json`。

最终专项记录：`playtests/v231-live-targeted-final.json`。早期估算基线：`playtests/v23-token-baseline.json`；模型可用性：`playtests/v23-live-model-probe.json`。所有模型用量为 Provider 报告的 Usage；未配置账户价格，不把 `estimated_cost=0` 解释为免费或实际账单。

## 复现

在本地环境或 `.env` 中设置自己的 `DASHSCOPE_API_KEY` 及上述 Base URL；不要把 Key 提交到版本库。安装依赖后运行：

```bash
PYTHONPATH=. LIVE_GAMES=2 python tests/live_dashscope.py
PYTHONPATH=. python tests/live_v23_checks.py
python -m unittest discover -s tests -p 'test_*.py' -v
```

前两项明确调用真实 API 并消耗账户额度；普通自动测试不调用真实模型。完整对局脚本设置 250 次请求阈值及 8 分钟时限；专项默认 18 次请求。可通过 `LIVE_REPORT`、`LIVE_CHECK_REPORT` 区分不同批次报告。
