# 05 — Mobile / PWA UX

## R-010 手机端体验增强

V2.1 不要求原生 App，继续以 Mobile Web + PWA 为主。

### 轮到玩家操作提示

当从 AI 发言、夜间等待等状态切换到“需要本人操作”时，应提供明显反馈：

- 顶部 / 中央醒目提示
- 页面标题变化（可选）
- 声音提醒开关
- 震动提醒开关（设备支持时）

默认不得强制播放高音量提示。

### Screen Wake Lock

游戏 ACTIVE 且页面在前台时，可尝试使用 Screen Wake Lock：

- 用户可关闭
- 浏览器不支持时正常降级
- 页面隐藏后应释放

目的：避免夜间阶段等待时手机自动息屏导致错过操作。

### PWA 安装提示

在 HTTPS 正式部署环境：

- Android/兼容浏览器可提示“安装到主屏幕”
- iOS 可提供“Safari -> 分享 -> 添加到主屏幕”的简短引导
- 不要频繁弹窗打扰

### 网络状态

手机弱网时应明确区分：

- 已连接
- 正在重连
- 已断开
- 状态同步中

重连后以服务器最新 snapshot 为准。

### 操作防抖

投票、技能、开始游戏等关键按钮：

- 提交后立即进入 pending / disabled 状态
- 收到成功或明确失败后恢复
- 不因双击产生重复 action
- 配合服务端 action_id 幂等

### 可触控性

关键按钮推荐：

- 触控区域不小于约 44x44 CSS px
- 不依赖 hover
- 底部操作栏考虑 iPhone Safe Area

### Provider 状态

手机大厅也必须能看到模型状态：

```text
OpenAI：可用
Claude：未配置
Gemini：可用
Mock：可用
```

避免用户在手机上选择一个实际无法使用的 Provider。
