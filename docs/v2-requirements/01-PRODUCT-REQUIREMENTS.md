# AI 狼人杀 V2 --- 产品需求

## 1. 真人玩家

真人进入房间并占一个座位，正常参与发言、投票和角色技能。轮到真人操作时暂停该玩家回合等待输入；真人死亡后进入观战状态。

## 2. AI 玩家

AI
可以直接占座位，自主分析、发言、投票和使用技能。不同座位可以配置不同模型，例如
OpenAI、Claude、Gemini 或 Mock AI。

AI 只能提出动作请求，不能直接修改 GameState。

示例：

``` json
{"action":"vote","target":3}
```

服务器 Rule Engine 验证合法性后才执行。

## 3. 房间系统

禁止使用单个全局 GameState。每局必须拥有独立 `room_id/game_id`。

需要支持： - 创建房间； - 加入房间； - 真人 + AI 混合房； - AI
自动补位； - 房间状态； - 开始游戏； - 后续可扩展邀请码。

多个浏览器、多个用户、多个房间不能串局。

## 4. 信息权限

建立统一 `InformationScope / PlayerView`。

服务器根据玩家身份生成"该玩家真正可见的数据"，然后才交给 AI 或前端。

村民视角可以看到公开发言、公开死亡、公开投票、自己的身份。

预言家额外看到自己的查验结果。

狼人额外看到合法狼队信息和狼队频道。

女巫只能看到规则允许的夜间信息。

绝对禁止把完整隐藏 GameState 交给 AI 后再仅靠 Prompt 要求"不许作弊"。

## 5. 规则引擎

Rule Engine 必须检查： - 玩家是否存活； - 当前阶段； -
是否轮到该玩家； - 动作类型是否合法； - 目标是否合法； -
技能是否已使用； - 玩家是否拥有对应角色能力； - 是否重复提交。

AI 永远不能直接写 GameState。

## 6. AI 记忆

每个 AI 玩家维护局内记忆： - 玩家发言； - 投票历史； - 怀疑度； -
身份推测； - 已确认事实； - 未确认猜测； - 发言矛盾； - 自己之前的判断。

事实和猜测必须分离。

AI 宠物可预留长期记忆： - 主人的玩法偏好； - 常用策略； -
喜欢简短/详细建议； - 历史游戏统计。

长期记忆可以后续实现，但数据库结构/API 应预留。

## 7. 模型配置

允许后台配置不同座位使用不同模型。

API Key 只能存在服务器环境变量，绝不能发送给浏览器。

需要处理： - 超时； - 重试； - JSON 异常； - 模型不可用； - fallback 到
Mock AI； - 并发限制； - Token/成本控制。

## 8. 持久化与恢复

游戏状态不能永久只存在 Python 进程内存。

根据规模可先使用 SQLite/PostgreSQL，并预留 Redis。

刷新网页、WebSocket 断线重连、服务器重启后，应尽可能恢复： - 房间； -
当前阶段； - 当前回合； - deadline； - 玩家公开状态； - 聊天记录； -
合法的私人状态。

## 9. 部署

继续保持： - Docker； - Render； - 环境变量； - 手机浏览器； - HTTPS
公网访问； - PWA。
