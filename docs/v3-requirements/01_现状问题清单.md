# 01. V2.3.1 现状问题清单

## 1. UI 不像真正狼人杀

当前界面偏“后台管理/信息面板”，玩家、当前发言、公共记录、操作区相互分散。

实际问题：
- 当前谁在说话不够突出；
- 需要上下滑才能知道发生了什么；
- 玩家头像存在感弱；
- 游戏过程不像传统狼人杀 App；
- 对话没有成为视觉中心。

## 2. 对话与流程没有集中显示

狼人杀最重要的信息应该是：
1. 谁在说；
2. 他说了什么；
3. 谁刚结束；
4. 下一位是谁；
5. 现在处于什么阶段。

当前这些信息分布在不同区域，用户需要主动找。

## 3. 声音功能名义存在但实际体验不可靠

页面有“开启声音/停止朗读”等功能，但试玩时实际上没有听到应有声音。

问题包括：
- 手机浏览器自动播放限制；
- 没有可靠的首次音频解锁；
- 提示音和 TTS 混在一起；
- 播放失败时没有明确反馈；
- UI 可能显示启用，但用户实际听不到。

## 4. 创建房间需要手动选择座位

创建/加入时要求用户先选 1～6 号座位，不符合自然游戏流程。

系统本应默认随机分配空座，手动换座只能作为可选功能。

## 5. 时间调度浪费大量时间

当前部分阶段依赖倒计时归零才推进。

结果：
- AI 已经完成操作，仍然等待；
- 狼人已选完目标，仍然等待；
- 预言家查验完成，仍然等待；
- 女巫已经决定，仍然等待；
- 玩家已经完成动作，剩余倒计时仍然被浪费。

倒计时被当成“固定阶段长度”，而不是“最大等待时间”。

## 6. AI 被规则系统过度约束

当前系统会生成类似：
- belief state；
- action decision；
- expression plan；

再要求模型按既定计划表达。

后果：
- AI 不真正自主做判断；
- 不同模型容易说出相似的话；
- 第一轮经常统一说“信息不足”“先观察”“不能下结论”；
- 模型难以主动站边、诈身份、撒谎、施压、试探；
- 测到的是平台策略，而不完全是模型能力。

## 7. 模型目录太固定

当前主要围绕少数 Provider / Model 展示。

问题：
- 无法从账号动态获取实际模型；
- API 明明可以接大量模型，但前端只给少数固定选项；
- OpenAI-compatible 平台无法成为一等公民；
- 不适合模型横向竞技。

## 8. 用户无法方便使用自己的 API Key

如果 API Key 只能由部署者放在服务器环境变量里，那么普通用户只能依赖站长配置。

结果：
- 无站长 Key 时只能使用 Mock；
- 用户不能带自己的模型参加；
- 公开网站缺乏真正可用性。

## 9. 人数固定为 6 人

座位、角色、补位、前端布局等都围绕 6 人写死。

现代狼人杀不应被固定在 6 人模式。

## 10. 角色过少

当前主要角色结构过于简单，无法覆盖现代狼人杀常见玩法。

## 11. 游戏模式固定

缺少：
- 9 人局；
- 12 人局；
- 多种板子；
- 自定义角色组合；
- 可扩展规则体系。

## 12. AI 能力测试结果存在“规则污染”

如果服务器提前决定：
- 怀疑对象；
- 投票目标；
- 表达观点；
- 谨慎程度；

最终结果就不能完全代表模型本身的社会推理能力。
