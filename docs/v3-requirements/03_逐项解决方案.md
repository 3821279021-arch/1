# 03. 逐项解决方案

## 1. UI：改成左右玩家 + 中央舞台

### 目标
玩家头像固定在左右，中间显示完整实时游戏过程。

### 建议布局
- 左侧：一半玩家头像；
- 右侧：另一半玩家头像；
- 中间顶部：天数、昼夜、阶段、当前玩家、倒计时；
- 中间主体：对话流 + 系统流程；
- 中间底部：当前用户可执行操作。

### 玩家状态
头像卡应显示：
- 座位号；
- 玩家名；
- 真人 / AI；
- AI 实际模型；
- 当前发言；
- 思考中；
- 已投票；
- 死亡；
- 断线。

### 历史
全量历史移到抽屉/详情，不抢主舞台。

---

## 2. AI：从“服务器替 AI 决策”改为“服务器只管合法性”

服务器只提供：
- 本人身份；
- 本身份合法可见的私有信息；
- 公共发言；
- 公共事件；
- 当前允许动作；
- 合法目标；
- 基础规则。

模型自行决定：
- 怀疑；
- 站边；
- 投票；
- 夜杀；
- 查验；
- 发言；
- 是否诈身份；
- 是否撒谎；
- 是否改变立场。

服务器只负责：
- 防止越权信息；
- 校验动作是否合法；
- 超时；
- API 错误；
- 非法输出重试。

核心原则：

> 限制 AI 能看到什么，不限制 AI 必须怎么想。

---

## 3. 声音：提示音与 TTS 分开

### 提示音
用本地音频文件，保证稳定：
- 轮到自己；
- 开始发言；
- 结束发言；
- 投票开始；
- 天黑；
- 天亮；
- 游戏结束。

### TTS
单独控制：
- AI 发言朗读开关；
- 语速设置；
- 首次开启立即播放测试音；
- 播放失败明确提示。

### 移动端
首次点击“启用声音”时执行 audio unlock，适配 iOS/Safari。

---

## 4. 座位：默认随机

### 创建
不再传必选 seat。

服务器随机选空座：
`random.choice(available_seats)`

### 加入
默认随机分配。

### 高级
大厅中再提供“换座/指定座位”。

---

## 5. 时间：事件驱动推进

倒计时只表示“最长等待时间”。

规则：
- 发言完成 → 下一位；
- 投票全部完成 → 立即结算；
- 狼人全部提交 → 下一阶段；
- 预言家完成 → 下一阶段；
- 女巫提交/跳过 → 天亮；
- 无可行动角色 → 直接跳过；
- AI 完成 → 不等待剩余时间。

超时只处理未提交者。

---

## 6. 模型目录：动态获取

### 原生 Provider
支持：
- OpenAI
- Anthropic
- Gemini
- DashScope

### OpenAI-compatible
支持：
- Base URL
- API Key
- `/v1/models` 自动发现
- 手动 model ID 兜底

这样可覆盖大量第三方模型平台。

---

## 7. 用户 API（BYOK）

前端新增“模型与 API”页面。

流程：
1. 用户选择 Provider；
2. 填 Base URL（如需要）；
3. 填 API Key；
4. 后端测试连接；
5. 获取模型目录；
6. 用户把模型分配给 AI 座位。

安全：
- HTTPS 传输；
- 后端加密保存；
- 前端只看掩码；
- 永不回传完整 Key；
- 永不进入日志/Prompt/WebSocket。

---

## 8. 多人数

把人数抽象为 GameMode：
- 6 人极速；
- 9 人标准；
- 12 人标准；
- 自定义。

前端根据人数动态布局，不再固定 6 张卡。

---

## 9. 角色模块化

每个角色定义：
- key
- 名称
- 阵营
- 行动阶段
- 合法目标
- 私有视野
- 技能效果
- 死亡触发
- 特殊胜利条件

新增角色不再修改大量核心 if/else。

---

## 10. AI 竞技数据

每个 AI 座位记录：
- 模型；
- 阵营；
- 胜负；
- 发言；
- 投票；
- 技能动作；
- 判断变化；
- 延迟；
- token；
- 成本；
- 错误；
- fallback。

这些用于赛后分析，不应用来约束当局模型。
