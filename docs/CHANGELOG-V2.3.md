# V2.3 变更与升级

基于用户提供的 V2.2 原工程和 V2.3 建议包实现，继续使用 FastAPI、SQLite、六人规则、四家模型、Docker/Render 和 PWA。

## 成本、记忆与策略

`tokens.py` 提供统一 `estimate_tokens(provider, model, text)`：OpenAI 优先使用 tiktoken；V2.3.1 新增随包提供的 Qwen2/3 文本词表，运行时无需下载。未知模型/词表不可用时回退经验估算；其他 Provider 使用明确系数。路由按实际 Usage 的最近 32 次数据校准模型系数，预算加入默认 15% 余量。OpenAI 词表首次加载可能下载公共文件，网络失败会回退；上下文构造与计数在后台线程完成。未验证的模型需要实测。

每种记忆列表都有上限，溢出内容折叠到固定六人范围的角色/查验/立场索引、票型统计、自身选择及判断摘要。每日摘要保留最近三天。摘要继续保留 event_id、来源、visibility 和 confirmed，不把玩家声明升级为真实身份。旧怀疑和策略证据按天衰减。

Prompt 分为永久规则、合法当前视角、长期摘要、最近事件、服务器策略和当前任务。去掉 UI/音色/执行标签和重复记忆，默认 6000 Token 的提示裁剪阈值为当前任务预留空间。V2.3.1 对复杂摘要也执行预算裁剪，保留自身已确认查验；裁剪只影响请求投影，原始记忆和公开历史继续保存。

`GameBeliefState` 维护阵营/角色概率、可信度、声明一致性、票压、关系、证据与计划。公开身份冲突、前后矛盾、票型和低置信度自然语言怀疑进入启发式评分；自己的查验优先级最高。狼人私有计划仅从其合法视角构造，公开表达点不携带私有证据。

默认 `AI_STRATEGY_MODE=server`：服务器先决定动作，模型返回结构化动作并表达发言；不同表达模型或 Mock 回退沿用同一决策。可选 `model` 模式保留模型在合法目标内决策，失败时仍使用服务器策略。V2.3.1 的公开表达仅接收公开记录、公开记忆与表达计划；预言家真实查验用服务端生成的准确前缀展示，模型不能改写，接续句子经局部语义校验。模型仍可能误判或遗漏证据，启发式没有胜率保证。

## 模型与可观测性

复用应用生命周期内的 AsyncClient，关停时关闭连接和待写成本记录。Adapter 提供统一生成、流式、估算、Usage 接口，统一结果包含文本、解析 JSON、Provider/模型、输入输出 Token、延迟和路由结果。

OpenAI 使用 Responses JSON Schema，Claude 使用指定 Tool schema，Gemini 使用 responseJsonSchema；DashScope 保持兼容 JSON 模式，统一执行本地动作格式/类型/合法目标检查。默认一次失败修复重试，每次请求分别预留预算；再失败切换 Provider 或 Mock。结构化输出始终经过 RuleEngine，未改动过期 AI 丢弃及 action_id 幂等约束。

记录 room/game/agent/day/phase/request、估算/实际输入、输出、延迟、模型和回退原因，不记录 Prompt、密钥或响应正文。Gemini 的推理 Token 也计入输出用量。SQLite 独立保存模型请求与路由记录，房主结束后可下载成本报告，重启后保留记录。缺失 Usage/价格的费用仍明确标为估算。

## 多人、安全与恢复

大厅房主可踢出真人、锁定/重新开放房间、设置/移除密码，解除某座位原玩家的重入限制。开局后禁止踢人和改入座权限，避免破坏角色分配与历史。房间密码使用随机盐 PBKDF2，不进入任何浏览器快照。

首次会话生成 80 位随机恢复码，服务端只存 SHA-256 摘要。使用恢复码恢复相同 owner_id/座位/房主身份，同时轮换 Token 和恢复码；旧设备连接立即关闭，旧码不可再次使用。提供恢复码重发、Token 轮换、主动撤销接口；默认会话期限 30 天，恢复码沿用期限，过期清理。房间结束后的游戏动作由规则层拒绝，身份仍可进入其他房间或原班重开。

Join/chat/action/reconnect 分别校验房间与会话限流，恢复码验证按 IP 限流。WebSocket 在第一帧带 Token 和最后 event_id，重连统一返回服务器权威快照；动作只经 HTTP，并继续使用原 action_id 重试。服务端重验撤销与到期状态。

所有 HTTP 响应添加 CSP/nosniff/Referrer-Policy/Permissions-Policy；API 使用 no-store，Service Worker 只缓存公开应用壳。沿用所有昵称/聊天/模型内容转义。

## 存储、前端与工程

SQLite 自动添加 room_events/player_memory/model_telemetry 边界，语义事件与快照在同一事务提交。流式碎片仍走事件推送，结束后提交正文；未新增事件回放 UI。热路径 SQLite 读写、限流持久化和维护任务移到线程，并用锁串行访问；取消保存任务时等待写入完成，避免读写可变状态发生竞争。

ACTIVE/FINISHED 保留完整状态；闲置大厅默认 6 小时归档，结束默认 14 天归档；ARCHIVED 默认再保留 14 天，之后删除快照、聊天、私有记忆、事件与模型明细，仅留下匿名统计。清理包含 SQLite 页面压缩与 WAL 截断。私有宠物偏好在身份和所有房间均不再引用后清理。

app.js 改为模块入口；api/socket/store/lobby/game/pet/audio/pwa/main 及 UI/事件模块分别承担职责，传输不直接操作 DOM。生产与开发依赖锁定，GitHub Actions 运行编译、JS 语法、规则/隔离/长局/API、三套浏览器和 Docker smoke。

本版本仍明确要求单 worker / 单实例，不声称支持 PostgreSQL、Redis 或分布式调度。9/12 人、更多角色、观战、成长/排行等按建议保留给后续版本。

## 从 V2.2 升级

1. 停止旧进程，备份原 SQLite 文件；用 V2.3 源码和 requirements.txt 安装依赖。
2. 继续设置原 DATABASE_PATH，单 worker 启动。表结构自动迁移；现有 Token/房间可读取，旧记忆在读取或接收事件时压缩。
3. 原设备进入首页「身份恢复与会话」，生成并保存恢复码；已有 Token 不会凭空知道新码。
4. 复核 .env.example 的预算、策略和归档保留期。归档清理会实际删除到期明细。
5. 原 PWA 壳缓存升级为 v23-modules；联网刷新一次获取新模块。
